# Trails in the Sky 2nd Chapter compatibility

This branch adds **offline** support for the Clouded Leopard Entertainment Steam build checked on 2026-09-27: Steam build 25386012, `sora_2nd.exe` file version 1.3.2.0, SHA-256 `D8B2911D1576216BDC22D070550E4F531E105DE7ED2981885849669F4ACF8AAF`.

## Verified on the installed game

- The earlier FPAC audit exported 170 chr-prefixed MDLs at width 100%, reparsed each result, and checked finite positions, triangle indices, skin-weight sums, material order, mesh counts, and unchanged model size. All 170 passed: 88 MDL v4 and 82 MDL v5. That broad prefix included one noncanonical `chrx010.mdl` and excluded costume suffixes. The editor now selects 169 `chr####.mdl` base models and 301 complete `chr####_c##.mdl` costume models. Three flat planes initially failed a height assumption; width editing now uses their nonzero axis span. See `smoke/second_assets.py`.
- The separate 2nd age catalog contains 31 adults and 7 minors with stated evidence; `chr5345` is explicitly labeled 11 years old in the game's name table. `chr5710` is labeled as a bridal outfit but reuses `chr5500` face and hair parts, so its identity and age remain unverified. Exact 2nd ages were not inferred from 1st data. The shared age policy is a deny-list of minors: a model the catalog does not list is treated as a defaulted adult, `chr5710` (catalogued as `unverified`) is eligible under the same rule, and only catalogued minors stay restricted to width editing. The studio labels unlisted models "年龄目录未登记 · 默认成年" and unverified ones "身份与年龄未核实 · 默认成年". Each of the 31 adults passed chest export at strengths −500 and +1000 with round-trip, topology, finite-value, Jacobian, and face-direction checks. See `smoke/second_chest.py`.
- The first visual report exposed a missing bind-pose transform: `chr5344` hair floated above the child face. The preview now skins each visible mesh group from its own bind matrices into the model skeleton, including weighted facial and hair bones. `smoke/second_preview_alignment.py` audited the earlier 170-model set, and the WPF regression reopens the reported `chr5344` and `chr5710` inputs. Diagnostic captures are kept outside the release package.
- The 2nd Chapter name table identifies `chr5000.mdl` as Estelle's 1st Chapter outfit and `chr5000_c11.mdl` as her 2nd Chapter light outfit; `chr5000_c10.mdl` is a separate full model with a scene alias. The older scanner suppressed every underscored MDL, which hid the outfit variants. The updated WPF check scanned 169 base plus 301 costume models, previewed both Estelle outfits and v4/v5 models, exercised the loading state, and exported an MDL locally. A captured offscreen preview shows visibly distinct 1st and 2nd outfits. It then installed a width-adjusted `chr5000_c11.mdl` under its exact path and restored the original in an isolated copy of the game executable and model. The installed game's executable and selected model hashes, PAC sizes/times, and game-root XInput proxy state did not change. See `smoke/SecondChapterCheck.cs`.
- A separate read-only audit exported and reparsed all 301 complete `chr####_c##` costume models at width 100%. All 301 passed geometry, skin-weight, bone-index, material-name-order, model-header and byte-size checks: 141 MDL v4 and 160 MDL v5. The report is kept outside the player ZIP under `release-artifacts/second-costumes-audit-20261007.summary.json`. This verifies the structure of the generated files, not their selection or animation in a live game.
- The 2nd installer now creates a package containing exactly `xinput1_4.dll` from sora2looseload and one generated `asset/common/model/<id>.mdl`. It rejects a different existing proxy, backs up replaced files, hashes installed bytes, rolls back an interrupted copy, and supports undo. These cases passed against an isolated copy of the 2nd executable and a generated model; the actual game directory was not written during this test. See `smoke/SecondInstallCheck.cs`.
- The 1st Chapter `chr5002` model still passed width preview and export with the updated Python tools.

To rerun the model audits, set `SKY_STUDIO_TOOLCHAIN` to a local checkout containing Kuro MDL Tool, then run the two scripts with `--game` pointing to the installed 2nd directory and `--report` pointing to a writable local JSONL path. The WPF check also requires `SKY2ND_GAME_ROOT`. Tests write their outputs under the studio workspace; they do not write to the game.

## Game installation

The bundled ED9Loader, EventStarter, and SceneRedirect components target specific 1st Chapter executable addresses. The 2nd path uses the separately bundled sora2looseload XInput proxy and installs only a generated loose MDL at `asset/common/model/<id>.mdl`. Installation checks the game EXE's x64 PE format and the presence of readable character models without requiring the inspected 1.3.2.0 hash. The player ZIP includes the 2nd-specific DLL at `runtime/second-loader/xinput1_4.dll`; the studio checks its PE architecture, XInput ordinal exports, loader markers, and the inspected 49,664-byte SHA-256 `E08A18068A482BB5D187A62023759C0E14AB69D76395B773EF0405D35E2AC8C7` before using it. The player does not need to download or choose a DLL. A different game-root XInput DLL is never overwritten. The original PAC and EXE stay untouched. Other 2nd builds, including the reported 1.03.1, still require a real in-game test.

The [sora2looseload project](https://github.com/lmaple0/sora2looseload) documents static checks for build 25386012. Its v1.1.2 notes report that the affected Steam 1.3.2 system started normally with the proxy. This studio's generated MDL has not yet been checked visually in game. No game executable or third-party mod resources are included in source control or reports.

**Remaining game check:** confirm which Estelle model ID a particular scene and costume selection uses, install that edited model into the actual game, restart it, inspect its materials and animations in a free-roaming scene, and confirm that Undo restores the original. A model's resource label alone does not prove when the game loads it. Additional costumes and extreme slider values need representative in-game checks. The isolated tests above do not establish these results.
